# OBS를 늘 디버깅 옵션으로 켜기 — 설계 (작은 변경)

날짜: 2026-11-11

## 왜

플러그인은 OBS가 `--remote-debugging-port`로 켜져야 동작합니다. 지금은 사용자가 바로가기를 손으로 고쳐야 하고, 잊거나 OBS 업데이트로 옵션이 지워지면 키가 이유 없이 `OFFLINE`이 됩니다. 사용자는 **다른 사용자들도 버튼 한 번으로 고정해서 켤 수 있게** 하고, 디버깅 모드의 문제점도 알려 주고 싶어 합니다.

## 확인한 것 (2026-11-11, 이 PC)

- 포트는 `127.0.0.1:9222`에만 열립니다(주인 프로세스 `obs64`).
- **웹페이지에서는 못 들어옵니다**: 웹페이지처럼 `Origin: https://evil.example`을 붙인 WebSocket은 **403 거절**. 다른 Host 이름으로 목록을 요청하면(DNS 재바인딩) **500 거절**. 이 PC의 프로그램(Origin 없음)만 연결됩니다.
- `/json/version`의 User-Agent에 `OBS/32.0.4`가 들어 있어 **OBS인지 구분할 수 있습니다**.
- 바로가기 3곳: `C:\Users\Public\Desktop\OBS Studio.lnk`, `C:\ProgramData\...\Start Menu\Programs\OBS Studio.lnk`(둘 다 공용 위치라 고치려면 관리자 권한이 필요하고, OBS 설치 프로그램이 업데이트 때 다시 만듭니다), 작업 표시줄 고정 `%APPDATA%\...\User Pinned\TaskBar\OBS Studio.lnk`(사용자 폴더). 시작 프로그램 등록은 없음.

## 디버깅 모드로 켤 때 생길 수 있는 문제 (README에 씁니다)

1. **이 PC 안의 다른 프로그램**은 OBS 안의 페이지(로그인된 치지직·씨미 스튜디오, 위플랩 리모컨 등)를 보고 조작할 수 있습니다. 인터넷이나 일반 브라우저의 웹페이지에서는 들어올 수 없습니다(위 확인). → 모르는 프로그램을 설치하지 않는 것이 가장 중요합니다.
2. **포트 충돌**: 다른 프로그램(크롬 개발 모드 등)이 같은 포트를 쓰면 OBS가 포트를 못 열거나, 플러그인이 엉뚱한 브라우저에 연결될 수 있습니다. → 아래 안전장치 1, 설정에서 포트 바꾸기.
3. **옵션 없이 켬**: 원래 아이콘·시작 메뉴로 켜거나 다른 프로그램이 OBS를 켜면 옵션이 빠집니다. → 안전장치 2.
4. **OBS 업데이트**: 설치 프로그램이 공용 바탕화면·시작 메뉴 바로가기를 다시 만들어서, 거기에 붙인 옵션은 사라질 수 있습니다. → 전용 바로가기는 사용자 폴더라 그대로 남습니다.
5. 성능 영향은 거의 없습니다(포트는 기다리기만 하고, 플러그인은 토글 키만 1초에 한 번 확인).

## 정한 것 (사용자): 전용 바로가기

설정 창 아래쪽(디버깅 포트 옆)에 **[OBS 바로가기 설정]** 버튼과 결과 한 줄을 둡니다. 누르면 플러그인이:

1. OBS 위치를 찾습니다: 레지스트리 `HKLM\SOFTWARE\OBS Studio`의 기본값(설치 폴더), 없으면 `C:\Program Files\obs-studio`. `bin\64bit\obs64.exe`가 없으면 "OBS를 찾지 못했어요"라고 알리고 아무것도 바꾸지 않습니다.
2. **내 바탕화면**(OneDrive로 옮긴 바탕화면 포함, Windows가 알려 주는 위치)과 **내 시작 메뉴**에 `OBS Studio (Browser Click).lnk`를 만듭니다. 대상 `obs64.exe`, 인수 `--remote-debugging-port=<설정 포트>`, 시작 위치 `bin\64bit`, 아이콘은 OBS 것. 이미 있으면 덮어씁니다.
3. **작업 표시줄에 고정된 OBS 바로가기**가 있으면 인수에 같은 옵션을 붙입니다(이미 있는 `--remote-debugging-port=…`는 새 값으로 바꾸고, 다른 인수는 그대로 둠).
4. 결과를 알립니다: "바탕화면·시작 메뉴에 'OBS Studio (Browser Click)'를 만들었어요. 작업 표시줄의 OBS에도 옵션을 붙였어요. 이제 이 바로가기로 OBS를 켜세요."
- 관리자 권한이 필요 없습니다. 공용 바로가기는 건드리지 않습니다.

## 안전장치

1. **OBS인지 확인**: `/json/version`의 User-Agent에 `OBS/`가 없으면 OBS가 아닌 것으로 보고 **아무것도 누르지 않으며**, 키는 `OFFLINE`, 로그에 "port is not OBS".
2. **옵션 없이 켜진 OBS 알림**: 포트에 연결이 안 되는데 `obs64.exe`가 실행 중이면, 키 제목을 `OFFLINE` 대신 **`디버그\n꺼짐`**으로 보여 줍니다(프로세스 확인은 실패했을 때만, 5초에 한 번).

## 하지 않는 것

- 공용 바로가기 수정(관리자 권한, 업데이트로 지워짐), OBS 자동 재시작, 레지스트리로 실행 옵션 끼워 넣기(백신이 의심하는 방식).
- macOS.

## 방법 비교

- **A(고름) 사용자 폴더에 전용 바로가기 + 작업 표시줄 고정에 옵션** — 권한 불필요, 업데이트에 안 지워짐. 대가: 사용자는 새 바로가기로 켜야 함(공용 바탕화면의 원래 아이콘은 옵션 없음).
- B 기존 바로가기 3개 수정 — 관리자 권한 창, 업데이트 때 지워짐.
- C README 안내만 — 사용자마다 손으로 해야 함.
