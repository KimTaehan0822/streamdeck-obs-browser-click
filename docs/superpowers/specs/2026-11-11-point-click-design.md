# 범용 클릭: 캡처 화면에서 위치 찍어 누르기 — 설계 (작은 변경)

날짜: 2026-11-11 · 앞 설계: `2026-11-10-obs-browser-click-design.md`

## 왜

범용 클릭은 지금 "버튼 글자"나 "CSS 선택자"로만 누를 수 있습니다. 위플랩 후원 알림창처럼 **버튼이 아닌 영역**(알림 자체를 클릭해서 넘기기)이나 글자·선택자로 잡기 어려운 곳은 누를 수 없습니다. 사용자는 그 페이지 화면에서 **원하는 곳을 찍어서** 키에 할당하고 싶어 합니다.

## 확인한 것 (2026-11-11)

- `Page.captureScreenshot`로 독·브라우저 소스 화면을 캡처할 수 있습니다. 독은 탭 뒤에 있어도 실제 크기를 가집니다(위플랩 617×414, 씨미 617×416, 치지직 614×359, 브라우저 소스 500×400 등, 배율 1).
- `Input.dispatchMouseEvent`(이동 → 누름 → 뗌)로 좌표를 누르면 실제 클릭으로 동작합니다. 위플랩 `일시 중지` 버튼 자리(60,108)를 두 번 눌러서 `다시 시작`으로 바뀌었다가 원래대로 돌아오는 것을 확인했습니다.

## 정한 것 (사용자)

- 키 이름이 잘리는 문제는 **사용자가 스트림덱 앱에서 글자 크기를 조정**합니다. 플러그인은 바꾸지 않습니다.
- 위치는 **설정 창에 뜬 캡처 화면에서 마우스로 찍어서** 고릅니다.

## 설계

- 범용 클릭 설정에 **방식**을 추가합니다. `버튼으로 찾기`(지금 방식, 기본값)와 `위치 찍기`가 있습니다. 기존 키는 그대로 `버튼으로 찾기`로 동작합니다.
- `위치 찍기`를 고르면:
  - **[화면 불러오기]** 버튼을 누르면 플러그인이 고른 페이지를 캡처해서 설정 창에 보여 줍니다(JPEG).
  - 그림을 찍으면 그 자리의 **페이지 좌표**(CSS 픽셀, 캡처가 줄어 보여도 원래 크기로 환산)를 저장하고 빨간 점으로 표시합니다. X·Y 칸에서 숫자로 고칠 수도 있습니다.
- 키를 누르면 페이지의 현재 크기를 읽습니다. 좌표가 그 안이면 그 자리에 마우스 이동·누름·뗌을 보냅니다. 밖이면(독이 작아짐) **아무것도 누르지 않고** 경고를 띄웁니다.
- 키 제목은 `위치 X,Y`. 토글 상태는 없습니다.

## 하지 않는 것

- 독 크기가 바뀌었을 때 좌표를 자동으로 비율 보정하기. 반응형 페이지에서는 버튼이 비율대로 움직이지 않아서 오히려 틀린 곳을 누를 수 있습니다. _(제 판단)_ 어긋나면 다시 찍습니다.
- 찍은 자리를 버튼으로 바꿔 저장하기(사용자가 고르지 않은 방법).

## 실패로 치는 것

- 화면 밖 좌표를 누르거나, 페이지가 없는데 다른 페이지를 누르는 것.

## 방법 비교

- **A(고름) 캡처에서 찍은 좌표를 그대로 저장, 진짜 마우스 이벤트로 누름** — 버튼이 아닌 영역도 누릅니다. 대가: 독 크기·스크롤이 바뀌면 어긋납니다.
- B 찍은 자리의 버튼을 찾아 글자·선택자로 저장 — 크기 변화에 강하지만 빈 영역은 못 다룹니다. 사용자가 A를 골랐습니다.
- C X·Y 숫자만 입력 — 좌표를 알아내기 어렵습니다.
