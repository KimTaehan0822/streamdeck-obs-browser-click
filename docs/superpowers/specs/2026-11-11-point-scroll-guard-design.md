# 위치 찍기: 스크롤 경고와 스크롤 되돌리기 (짧은 설계)

## 왜

위치 찍기는 "보이는 화면 기준 X, Y"를 누릅니다. 독이나 브라우저 소스를 스크롤하면 같은 X, Y에 다른 내용이 와서 엉뚱한 곳이 눌립니다. 좌표를 계산으로 보정하지는 않고(사용자 결정), 틀어졌다는 걸 키로 알리고 저장한 스크롤로 되돌릴 수 있게 합니다.

## 목표

- 점을 찍을 때 그 캡처의 스크롤 위치(scrollX, scrollY)를 함께 저장한다.
- 키가 1초마다 하는 상태 확인 때, 위치 찍기 키는 페이지 스크롤도 읽는다. 저장값과 다르면 키 제목을 `스크롤\n바뀜`으로 바꾼다. 맞으면 원래 제목으로 돌아간다.
- 키 설정에 **[스크롤 되돌리기]** 켜기/끄기 (기본 켜짐, 키마다).
  - 켜짐: 스크롤이 다를 때 키를 누르면 페이지를 저장한 스크롤로 되돌리고 클릭하지 않는다. 다시 누르면 클릭한다.
  - 꺼짐: 스크롤이 다를 때 키를 누르면 아무것도 누르지 않고 ⚠만 띄운다.
- 설정 화면 [화면 불러오기] 옆에 **[스크롤 되돌리기]** 버튼. 스위치와 상관없이 그 페이지를 저장한 스크롤로 되돌린다.

## 변경 (구현 중, 사용자 승인)

실제 OBS 페이지 15개 중 페이지 전체가 스크롤되는 곳이 없었다 (위플랩·씨미·치지직 모두 안쪽 칸만 스크롤). 그래서 점을 찍을 때 **그 점이 들어 있는 스크롤 칸**을 찾아 CSS 경로(`scrollBox`, 페이지 전체는 `''`)와 그 칸의 스크롤을 저장하고, 경고·되돌리기도 그 칸 기준으로 한다. 칸을 못 찾으면(사이트 화면이 바뀜) 키는 `스크롤 바뀜`, 누르면 ⚠, 클릭 안 함. 치지직 채팅처럼 아래에서 쌓이는 목록은 스크롤 값이 음수라 음수도 허용한다. 아래 "페이지 안의 상자" 제외 항목은 이 변경으로 없어졌다.

## 하지 않는 것

- 좌표 자동 보정.
- 페이지 안의 상자만 따로 스크롤되는 경우의 감지 (페이지 전체 스크롤만 본다). 도움말에 적는다.
- 스크롤 정보가 없는 기존 키: 지금처럼 동작한다. 점을 다시 찍으면 새 기능이 적용된다.

## 방식 (고른 것: 1)

1. **상태 확인 때 스크롤도 읽기 (선택).** 누르기 전에 키에서 미리 보인다. 위치 찍기 키마다 1초에 한 번 페이지에 작은 질문(Runtime.evaluate)이 더 간다.
2. 누를 때만 확인. 코드는 적지만 미리 알 수 없다.

## 만드는 방법

- `cdp.ts`: 크기 읽는 식에 `scrollX`, `scrollY`(반올림)를 더한다. `screenshot`이 스크롤도 돌려준다. `scrollTo(wsUrl, x, y)` 추가.
- 설정 값: `scrollX`, `scrollY` (문자열, 찍을 때 저장), `scrollRestore` (불리언, 없으면 켜짐).
- `actions.ts`: 상태 `'scrolled'` 추가. poll과 onKeyDown에서 위치 찍기 키의 스크롤을 비교한다. 1px 차이까지는 같은 것으로 본다(내 판단: 배율 때문에 소수점이 생길 수 있음).
- `plugin.ts`: `restoreScroll` 메시지 → 그 키 설정의 스크롤로 되돌리고 결과를 설정 화면에 알린다.
- `click.html`: 스위치, 버튼, 안내 문구 ("크기를 바꾸거나 스크롤하면…").
- 되돌린 뒤에도 페이지가 짧아져서 그 위치까지 못 가면 경고가 그대로 남는다 (클릭 안 함).
- 도움말: README 3개, 설명서 HTML 3개와 PDF 3개 (키 표시 표에 `스크롤 바뀜` 줄 추가).
- 테스트: 경고 표시, 켜짐일 때 되돌리기만 하고 클릭 안 함, 꺼짐일 때 ⚠, 스크롤 정보 없는 키는 그대로.
